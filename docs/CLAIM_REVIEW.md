# Claim review

`review_claims(question, claims, contexts, history=None, *, approved_config=None, client=None)` in `parkguide.claim_review` performs one model criticism pass on a proposed answer. It returns ordered `decisions` (`claim_index`, `supported`, `reason`, `supporting_quotes`), provider `usage`, `elapsed_ms`, returned `model`, and `prompt_sha256`. Complete unique decision indices, strict field types, approved response model, usage, and completion status are checked before acceptance. A provider refusal or malformed review raises a safe `GenerationError`; any available charged usage is retained.

The wire schema asks for short witness IDs such as `W001`, selected from a catalog mechanically extracted from the actual source text. The adapter resolves each ID to its exact source/quote pair and rejects unknown, duplicated or uncited choices. This avoids asking the model to copy long text or reproduce a long source hash.

For a supported claim, every cited ID needs an exact contiguous source-text witness of 1–25 lexical words. Quotes may be split into short header/row or operand witnesses, but cannot be fabricated, paraphrased, duplicated or drawn from uncited passages. Unsupported decisions require no witnesses. The shared pure validator also protects injected reviewers in selected-park requests. Claim review is mandatory in the selected-park UI, even if the legacy diagnostic configuration toggle is off. Missing, failed or malformed review withholds factual output.

The adapter and answer generator call the same `Generator.request` helper against the shared Azure endpoint/key. Both use pinned Luna, temperature zero, reasoning disabled, a 1,000-token output ceiling, `store=False` and strict JSON. Owned clients are closed; redirects and SDK retries are disabled. It makes no fallback-provider choices, retries, budget reservations, database writes, or app decisions. The caller must reserve and settle the extra review call, bound transient retries, and withhold unsupported claims. Closed-book B0 remains a legacy diagnostic exception and is unavailable with an explicit selected park.

The reviewer receives only the union of the claims' actually cited passages, declared citations, question, and actual conversation history. Uncited retrieved passages and their witness IDs are removed before the review request, so they cannot supply omitted evidence. Per-claim citation checks still apply within that union. Each claim must be supported by its own cited passages. History clarifies references and constraints; generated history does not supply evidence. The criticism prompt specifically checks entity/unit associations, negative table-cell claims, stale dates, and clearly described simple calculations from valid cited operands. Source/user instructions are untrusted data. Reasons are short paraphrases rather than copied source text.

This is an **AI support check, not a semantic guarantee or human verification**. It can wrongly accept unsupported claims or reject supported ones, and should be measured separately with actual reviewed examples. Offline mocked tests establish response/privacy/client contracts only. The initial implementation adds no dependencies beyond the existing OpenAI SDK. No live calls were made while authoring it.

## Observed live limitations

The claim reviewer is enabled in the selected configuration and its successful cost is included in response generation-cost estimates. Actual diagnostics exposed both directions of error: it accepted an insufficient map-based table-absence claim in an earlier conversation, and it withheld final B1 D001's noon answer after the model combined checkout with arrival date, using an awkward phrase also found in the FAQ. This is probable over-withholding with a legitimate date-wording concern; human adjudication is required. It can also miss causal embellishments. These cases are retained in immutable traces and AI review proposals; no reviewer decision is treated as human verification. Each successful factual request may require an additional paid model call and latency.
