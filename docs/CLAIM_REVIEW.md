# Claim review

`review_claims(question, claims, contexts, history=None, *, approved_config=None, client=None, citation_contract="all-cited-v1")` in `parkguide.claim_review` performs one model criticism pass on a proposed answer. It returns ordered `decisions` (`claim_index`, `supported`, `reason`, `supporting_quotes`), the `citation_contract`, provider `usage`, `elapsed_ms`, returned `model`, and `prompt_sha256`. Complete unique decision indices, strict field types, approved response model, usage, and completion status are checked before acceptance. A provider refusal or malformed review raises a safe `GenerationError`; any available charged usage is retained.

The wire schema asks for short witness IDs such as `W001`, selected from a catalog mechanically extracted from the actual source text. The adapter resolves each ID to its exact source/quote pair and rejects unknown, duplicated or uncited choices. This avoids asking the model to copy long text or reproduce a long source hash.

The default `all-cited-v1` contract and `validate_review_decisions` require an exact contiguous source-text witness of 1–25 lexical words for every cited ID of a supported claim. Quotes may be split into short header/row or operand witnesses, but cannot be fabricated, paraphrased, duplicated or drawn from uncited passages. Unsupported decisions require no witnesses. The shared pure validator also protects injected reviewers in selected-park requests. Claim review is mandatory in the selected-park UI, even if the legacy diagnostic configuration toggle is off. Missing, failed or malformed review withholds factual output.

Selected-park paid requests explicitly use `witness-selected-v1`. Its prompt asks the critic to select a nonempty minimum sufficient set of exact witnesses establishing the **entire unchanged claim**. Every witness must belong to that claim's original evidence IDs. The final citations are the witnessed subset, in their original order; no citation can be added or borrowed from another claim. An original citation that contributes no necessary witness may be omitted. The adapter and chat each run `select_reviewed_citations`, which first checks original ownership and exact quotes, then derives final IDs and applies strict validation against those final IDs. The chat recomputes selection rather than trusting returned selection metadata. Injected reviewers without an explicit contract retain the old strict behavior; malformed legacy responses are never silently salvaged.

The raw draft remains intact. Review traces record `citation_contract` and `citation_selections` with each original claim index, `original_evidence_ids`, and `final_evidence_ids`. Rejected claims have an empty final selection. Claim text is never shortened or repaired by this process. Displayed claims, citation links and source witnesses use the final IDs.

The adapter and answer generator call the same `Generator.request` helper against the shared Azure endpoint/key. Both use pinned Luna, temperature zero, reasoning disabled, a 1,000-token output ceiling, `store=False` and strict JSON. Owned clients are closed; redirects and SDK retries are disabled. It makes no fallback-provider choices, retries, budget reservations, database writes, or app decisions. The caller must reserve and settle the extra review call, bound transient retries, and withhold unsupported claims. Closed-book B0 remains a legacy diagnostic exception and is unavailable with an explicit selected park.

The reviewer receives only the union of the claims' actually cited passages, declared citations, question, and actual conversation history. Uncited retrieved passages and their witness IDs are removed before the review request, so they cannot supply omitted evidence. Per-claim citation checks still apply within that union. Each claim must be supported by its own cited passages. History clarifies references and constraints; generated history does not supply evidence. The criticism prompt specifically checks entity/unit associations, negative table-cell claims, stale dates, and clearly described simple calculations from valid cited operands. Source/user instructions are untrusted data. Reasons are short paraphrases rather than copied source text.

For `witness-selected-v1`, that request still contains the **original** cited union, including references later omitted from the final selection, so contradiction and exception checks do not lose those passages. A narrow deterministic glossary guard adds a rejection check: when a selected source contains a Markdown table header with an abbreviation, the claim uses an explicit glossary's full phrase, and an `ABBR = phrase` definition exists in supplied contexts, an own selected witness must contain that exact definition. A definition found only in uncited context causes rejection; it is never added to the claim or sent to the critic as support. The guard recognizes uppercase alphanumeric abbreviations, adjacent Markdown header/separator lines, and explicit equals definitions ending at a semicolon, period, pipe or newline. Full-phrase comparison ignores case and punctuation. It does not infer synonyms, interpret arbitrary legends, or establish table semantics on its own.

Witness selection deliberately relaxes coverage of **original proposed IDs**, while keeping every **final cited ID** bound to an exact witness. A critic that misses an essential clause can still choose insufficient support; the old all-ID rule could have rejected some such omissions. The glossary guard covers one observed pattern, not every missing condition or relation. This tradeoff must be measured with live examples and is not an equivalent semantic guarantee.

This is an **AI support check, not a semantic guarantee or human verification**. It can wrongly accept unsupported claims or reject supported ones, and should be measured separately with actual reviewed examples. Offline mocked tests establish response/privacy/client contracts only. The initial implementation adds no dependencies beyond the existing OpenAI SDK. No live calls were made while authoring it.

## Observed live limitations

The claim reviewer is enabled in the selected configuration and its successful cost is included in response generation-cost estimates. Actual diagnostics exposed both directions of error: it accepted an insufficient map-based table-absence claim in an earlier conversation, and it withheld final B1 D001's noon answer after the model combined checkout with arrival date, using an awkward phrase also found in the FAQ. This is probable over-withholding with a legitimate date-wording concern; human adjudication is required. It can also miss causal embellishments. These cases are retained in immutable traces and AI review proposals; no reviewer decision is treated as human verification. Each successful factual request may require an additional paid model call and latency.
