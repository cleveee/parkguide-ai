## User experience

1. A clear park selector (Yosemite, Yellowstone, Grand Canyon), initially unselected. Chat remains disabled until selection. Always show selected park near the composer/header; switching or clearing parks clears history and closes old evidence. New conversation resets only chat. Ignore stale in-flight replies from an old park or cleared conversation; disable double submission. Requests may finish on the server after browser cancellation; do not imply otherwise.
2. An elegant empty state with one clear action and useful non-gold suggested questions. Display real selected-park document/chunk counts once metadata loads, including capture age. Never preload fabricated conversations.
3. A comfortable conversation/composer with keyboard submit (Shift+Enter newline), disabled/loading/error states, measured latency and actual answer/refusal/clarification states. Never reveal a draft or stream claims before source review finishes. Loading is honest and indeterminate, with no made-up percentages, timings or stage-completion animation.
4. Delivered answer citations open a local evidence preview, with a separate official NPS link. Use source cards grouped by saved source page: title, park, HTML/PDF type, effective/capture date, exact saved excerpt, heading/PDF page, cited claims and source spans. Provide exact reviewer witnesses and clearly distinguish the displayed excerpt from the AI judgment. Retrieved but uncited passages belong in the retrieval inspector, never under Sources used. Unsupported/rejected claims cannot become delivered answer text.
5. A useful inspector (desktop side panel, mobile accessible sheet/dialog) with Evidence / Retrieval / Data flow views. Show actual retrieval query, filters, candidate/final counts, ranking scores with labels (cosine/BM25/RRF/reranker where present), timing, cache status if observed, source-selection IDs, generation/review returned model, token usage, estimated cost and reason for refusal/withholding. Distinguish metrics not captured from zero. Scores are ranking signals, never truth/confidence probabilities. Include safe structured raw JSON export and copy buttons, with no provider headers, keys, raw secret-bearing exceptions, unreviewed model draft, or unrelated private data.
6. A corpus browser reachable from the sidebar: read-only real SQLite counts by park, documents with search/filter, HTML/PDF/table flags and capture dates, stored sections/passages, chunk/index counts and model dimensions. Paginate/bound responses. Links and previews use validated official URLs and stored text; no iframe, remote fetching, unsafe HTML, traversal or SQL injection. Labels must distinguish all stored chunk builds from the active structure build and the selected park.
7. Transparent system explanation: question and selected park stay local through preflight; query embedding is sent to the one Azure endpoint when needed; saved NPS chunks are searched in local SQLite/NumPy/BM25 and reranked locally; question, selected snippets and bounded prior conversation go to Luna on that same Azure resource; claim reviewer receives only cited sources; unsupported claims are withheld; reviewed answer and saved source links return to browser. Source capture is a snapshot, not live conditions. History is browser-memory only unless explicitly documented otherwise. AI review does not establish human accuracy or guarantee no hallucination. Use “source review passed” or similar factual labels rather than “verified fact”.
